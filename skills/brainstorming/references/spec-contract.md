# Design Specification Contract

Write `docs/plans/YYYY-MM-DD-<topic>-design.md` (unless the user chooses another location). For multi-file/risky work, open with concise, stable-ID EARS requirements; trivial one-file changes use a one-line intent instead. Self-review placeholders, consistency, scope, ambiguity, and EARS/ID traceability.

Ask for explicit user approval after the review. If changes are requested, revise and re-review; do not proceed to implementation or planning until approved.
